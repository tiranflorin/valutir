# API

Send `Authorization: Bearer <token>` with authenticated requests. Errors are always JSON; validation failures return 422 with per-field `errors`.

- **Public:** `POST /api/register`, `POST /api/register/verify-email` (link token), `POST /api/login_check`, `POST /api/contact`, `POST /api/reset-password/request`, `POST /api/reset-password/new`, `POST /api/profile/email/confirm` (link token), `POST /api/reminders/unsubscribe` (signed link token), `POST /api/billing/webhook` (Stripe-signed), and `GET /health`.
- **Account (authenticated):** `GET`/`PATCH`/`DELETE /api/profile`, `PATCH /api/profile/password`, `POST /api/profile/email`, `POST /api/profile/email/verification` (resend the confirmation link), `GET /api/profile/export` (all of the user's data as a JSON download), `GET /api/profile/export/subscriptions.csv` (current subscriptions as CSV; optional `?view=personal|business`), `POST /api/logout`, `POST /api/logout/all`.
- **Billing (authenticated):** `GET /api/billing` (plan: `unlocked` when paid, `paidFeatures` when paid or an admin account; price; active-subscription usage), `POST /api/billing/checkout` (returns a Stripe Checkout URL).
- **Subscriptions (authenticated, owner only):** `GET`/`POST /api/subs`, `GET`/`PUT`/`PATCH`/`DELETE /api/subs/{id}`, `PUT`/`DELETE /api/subs/{id}/review` (flag for review with an optional note, or clear it), `DELETE /api/subs/{id}/price-changes/{changeId}` (remove a price change that was a correction; returns the subscription). Updates replace every field, so send the full subscription. Statuses: `active`, `trial`, `paused` (with an optional `resumesOn`), `cancelled`; the review flag is separate and survives updates. `manageUrl` is an optional `https` link (max 2048) to the provider's manage or cancel page; the API only stores it and never fetches it. `paidPersonally` (business only: paid with the owner's own card; ignored for a personal subscription) must be sent in every update too, and `payerChanges` (oldest first) keeps each switch with the card used before it, recorded the same way as price changes. `priceChanges` (newest first) is the price history: the server records one when an update changes `amount`, `currency` or `billingCadence`, never on the day the subscription was added, and a second change on the same day replaces the first.
- **Business (authenticated, owner only):** `GET /api/business/charges?month=YYYY-MM` (a month's charges of the owner's business subscriptions, current month by default, at most 36 months back, never a future month; each with `date`, `amount` and `currency` on that day from the price history, `paidPersonally` on that day, `upcoming`, and `invoiceFiled`), `PUT`/`DELETE /api/business/charges/{subscriptionId}/{date}/invoice` (tick or untick "Invoice filed"; 404 unless the date is a charge of that business subscription that has already gone out), and `GET /api/business/export.csv?from=YYYY-MM&to=YYYY-MM` (the accountant export: the charges that have gone out in 1 to 12 months, as CSV; 403 without paid features (the one-time unlock or an admin account); shares the 10-an-hour download limit). Charges are estimates counted from the billing date, as on the dashboard: none before the start date (or, without one, before the subscription was added), none for a paused subscription, and a cancelled one keeps its charges up to the cancellation date.

The full endpoint table with request details is in [AGENTS.md](../AGENTS.md#api-endpoints).

Notes:
- Password reset, email-change, and email-verification links use random single-use tokens; only their SHA-256 hash is stored. Reset links expire after one hour, email-change and verification links after 24 hours.
- "Download my data" (`/api/profile/export*`) is built on request and never stored: no password hash, token data, token hashes or Stripe IDs; `Cache-Control: no-store`; 10 downloads per hour per user (JSON and CSV together). CSV cells that start with `=`, `+`, `-`, `@`, a tab or a carriage return get a leading `'` so spreadsheets don't run them as formulas, and the file starts with a UTF-8 byte order mark for Excel. CORS exposes `Content-Disposition` so the app can use the suggested file name.
- Registration, password reset, contact, email confirmation and verification (opening a link: 10 per 15 minutes per IP; resending: 3 per hour per user), and password-checking account actions are rate limited.
- The contact form verifies the Turnstile token with Cloudflare server-side and sends the message to `CONTACT_RECIPIENT`, with the sender as Reply-To. Keep the Turnstile secret out of Vite variables.
